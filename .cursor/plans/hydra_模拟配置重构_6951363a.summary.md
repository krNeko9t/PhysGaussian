## Implementation Summary

### Step 1: `conf-skeleton` — Dependencies + Config Fragments
- Added `hydra-core` and `omegaconf` to `requirements.txt`
- Created `physics_sim/conf/` package with `__init__.py` (enables `pkg://physics_sim.conf` searchpath)

### Step 2: `scene-object-class` — SceneObject + Assembler
- **`physics_sim/scene/objects.py`** — `SceneObject` dataclass holding GS tensors, material, collider, mode, gs_type, etc.
- **`physics_sim/scene/assembler.py`** — `assemble_scene(cfg, renderer)` function that:
  - Deduplicates PLY loads via a cache
  - Supports three source strategies: `ply`, `id_map`, `sim_area`
  - Applies unified preprocessing: axis permutation → opacity filter → rotation → sim_area mask → position offset
  - Merges top-level material defaults with per-object overrides
  - Returns `list[SceneObject]`

### Step 3: `config-loader` — Hydra Programmatic Compose
- **`physics_sim/config/loader.py`** — `load_config(yaml_path)` that uses Hydra's `initialize_config_dir` + `compose` to resolve a root YAML (with `defaults:` and `searchpath`), returns a plain Python dict.

### Step 4: `pipeline-rewrite` — Streamlined Pipeline
- **`pipeline.py`** rewritten from 1348 → 807 lines:
  - CLI: only `--config`, `--white_bg`, `--compile_video`, `--no_render`, `--sh_degree`, `--raster_backend`, `--debug`, `--debug_log`
  - Flow: `load_config` → `assemble_scene` → partition by mode → concatenate → backend init → render loop
  - All ~350 lines of inline object assembly logic removed
  - No more `--ply_path`, `--backend`, `--cameras_json`, `--camera_mode`, `--output` CLI flags — all from config
